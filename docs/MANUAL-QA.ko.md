2026-10-14 · 문서·촬영 범위. 제품 JS/CSS·버전·배포 ZIP은 변경하지 않았습니다.

## 환경과 비용 경계

- Engine 2.4.6, build `2.4.6+9d3d6154d251`, 별도 빈 DATA_DIR·테스트 env·별도 Chromium 프로필.
- 합성 성인 캐릭터(28세)와 새 Conversation 채팅, 연결 없음·개인 대화 없음. 키는 가짜이며 화면에서 password 마스킹했습니다.
- 일반 화면: headless Chromium, 모바일 폭 390px 또는 데스크톱 1440px. 실제 확인창: 격리 Xvfb의 headed Chromium에서 창을 촬영·크롭했습니다. 호스트의 사용자 데스크톱을 촬영하지 않았습니다.
- 진단 2·셀피 확인창은 실제 native `confirm`이며 둘 다 취소했습니다. 해당 실행의 차단 라우트에 도착한 PixAI 요청도 **0건**입니다. 실제 생성·LLM 요청·갤러리 업로드는 실행하지 않았습니다.
- 기존 `real-` 이미지의 실기기 성공은 제공받은 근거입니다. 이번 QA의 실생성 결과가 아닙니다.

## 후속 실과금 QA 반영 (2026-10-14)

아래는 앞선 무과금 촬영과 **다른 실행의 결과**입니다. 이번 문서 정정에서는 유료 요청을 추가 실행하지 않았으며, 보존된 실행 기록·비용 영수증을 근거로 설명서에 반영했습니다.

- localhost 격리 QA에서 Tsubaki.2 / 1k / standard / batchSize=1로 실제 생성 POST 5회, 각 task `paidQuota` 2,700(합계 13,500). 잔액 전후 차액 측정이나 고정 가격 주장이 아닙니다.
- 셀피 2장·삽화 1장의 실제 생성·갤러리 저장, 삽화 메시지 첨부, 새로고침 후 3장과 첨부 유지 확인. 진단 2는 생성·다운로드 후에도 갤러리 미저장 확인.
- 접수 직후 긴급 중지한 작업도 `paidQuota` 2,700 유지, 제공자는 이후 completed. 확장은 저장 없이 `taskKnown` 미해결 영수증을 보존하고 새로고침 후에도 추가 생성을 차단했습니다.
- 삽화의 **Director 실행 결과 조회만 합성 fixture**입니다. 이후 PixAI 생성·갤러리 저장·첨부는 실제 동작이지만 실제 LLM Director부터의 전 과정으로 확대하지 않습니다. 셀피도 확장의 요청 대체 경로 확인이며 upstream 셀피 버튼 시작 동선은 미확인입니다.
- **iPhone·AWS의 진단 1·진단 2·프로필 읽기 후 무료 미리보기는 사용자 실기기 보고 수용**입니다. localhost 관측과 구분합니다. iPhone·AWS의 저장·첨부·유지·중지·키 삭제, 여러 기기 동시 사용 및 HTTPS 전반의 호환성은 미확인입니다.
- 최초 촬영의 24번 미촬영과 무과금 기록은 그대로 유효합니다. 후속 생성 성공을 촬영 당시의 성과로 바꾸거나 완성 화면을 합성하지 않았습니다.

## 개인정보 수정 후보

`extension.js:655–663`은 요청 `context`를 무조건 추가한 뒤, 최근 대화 옵션 ON일 때만 메시지 조회를 추가합니다. `extension.js:720–723`에서 각각 200자 제한을 적용합니다. 따라서 옵션 OFF가 모든 대화 관련 전송을 차단하지 않습니다.

**0.2.1 후보:** 최근 메시지 조회와 요청 context의 동의 경계를 일치시킬지, 별도 명시적 옵션으로 분리할지 결정해야 합니다. 이 예외를 설명서 5-7·7-3·알려진 제한과 README에 명시했을 뿐 제품 코드는 고치지 않았습니다. 최초 촬영에서는 실제 PixAI 전송 없이 공통 composer의 무료 preview로 확인했습니다. 후속 실과금 QA에서는 옵션 OFF의 합성 요청 context가 실제 유료 셀피 프롬프트에도 포함됐습니다.
